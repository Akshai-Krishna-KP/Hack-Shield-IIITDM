Engineering handbook

Shared conventions help us build software that's easier to understand, test, and maintain.

Engineering Enablement · Updated October 21, 2026

Small, reviewable changes

Prefer focused changes with a clear purpose. Keep pull requests easy to review and describe behavior changes, trade-offs, and any follow-up work.

Test the behavior

Cover the important paths and edge cases. Tests should explain intended behavior and catch regressions, not merely increase a coverage number.

Make operations part of the design

Include useful logs, health checks, and clear failure behavior. Avoid logging secrets or sensitive user data.

Before you merge

Check tests, review configuration changes, document operational impact, and confirm that secrets are supplied through approved mechanisms.

Leave the code clearer

Use descriptive names, remove dead code, and document non-obvious decisions where future maintainers will look for them.
